# 智途AI · 演示脚本

> 面向评审的 5 分钟演示路线。每一步都写清了「点什么、看什么、强调什么」。

---

## 演示前 60 秒准备

```bash
# 1. 数据库（只需执行一次，可重复执行）
powershell -ExecutionPolicy Bypass -File scripts/init-db.ps1 -DbPassword 你的密码

# 2. 后端
cd backend && mvn spring-boot:run

# 3. 前端
cd frontend && npm run dev
```

浏览器打开 http://localhost:3000，**提前登录好演示账号并停在首页**，避免现场等待。

> 演示账号：`13800000000` / `123456`（登录页有「一键体验」按钮）
>
> 该账号已预置画像、四年规划、7 天学习计划、6 条成长档案、AI 简历与通知，
> 所有页面一打开就有内容，不会出现空白页。

**如果现场网络不可用**：不配置 API Key 也能完整演示，
此时系统处于「离线模板模式」，界面会明确标注。这一点本身就是加分项——
说明团队没有把模板内容伪装成 AI 结果（可在「AI助手」页顶部看到状态徽章）。

## 第 0 步 · 开场（30 秒）

> 「市面上不缺 AI 聊天网站，缺的是把 AI 真正接进业务闭环的产品。
> 智途AI 的核心不是『能和 AI 聊天』，而是让 AI 参与大学生成长规划的完整链条：
> **采集学情 → 生成画像 → 生成四年规划 → 每日执行打卡 → AI 分析并动态调整 → 沉淀档案 → 生成简历**。」

**操作**：停在首页，指向中间的「成长闭环」进度条。

**强调**：这条闭环是产品的骨架，后面每一步都能在它上面找到位置。
六节点中已经点亮的节点数量，就是用户当前的完成度。

## 第 1 步 · 首页与学生画像（60 秒）

**操作**：
1. 指向右侧的**综合分环形图**与**能力雷达图**
2. 向下滚动到「AI 学生画像」卡片
3. 点开「今日建议」

**讲解要点**：
- 画像不是让 AI 随便夸人，而是把 9 项能力自评量化成 0–100 的分数，
  雷达图让「编程 72 分、算法 48 分」这种差距一眼可见
- 「优势 / 待提升」两栏是 AI 基于真实自评数据给出的，不是预设文案
- 首页右上角的**专业名来自数据库**（`major` 表 175 个专业），
  课程、规划、简历全都复用同一个专业 ID

> 如果评审追问「怎么保证 AI 输出结构稳定」：
> 提示词里强制约束 JSON 结构，后端解析失败会自动降级到规则模板，
> 并且降级状态会回传前端，界面上标注「离线模板」，绝不冒充 AI 结果。

---

## 第 2 步 · AI 四年规划（60 秒）

**操作**：
1. 进入「AI成长规划」
2. 指向高亮的**当前阶段**卡片（应高亮「大二」，与档案年级一致）
3. 展示分阶段的目标 / 课程 / 技能 / 竞赛标签
4. 滚到底部看「风险提醒」与「推荐证书」

**讲解要点**：
- 规划按大一到大四分四段，每段都有主题
- 大三、大四的路线是**跟着职业目标变的**：就业、考研、保研、考公四条路径内容不同
- 「风险提醒」是基于学情的预警，例如「数据结构没学好 → 后续算法和面试都会受影响」

**技术亮点**：当前年级从档案动态读取（早期版本写死为「大二」，这是一个真实的 bug，已修复）。

---

## 第 3 步 · 动态学习计划与打卡（60 秒）

**操作**：
1. 进入「成长档案」→「学习打卡」
2. 勾选今天的一条任务完成
3. 点「AI 分析我的进度」

**讲解要点**：
- 计划不是一次性的：AI 会读取你的**完成率与课程进度**，重新排后续任务，弱项优先
- 这就是「动态」二字的含义——计划会跟着你的真实执行情况走

---

## 第 4 步 · 竞赛推荐（45 秒）

**操作**：
1. 进入「竞赛中心」→ 切到「AI 推荐」标签
2. 指向每个推荐卡片的**匹配度评分环**和「推荐理由」

**讲解要点**：
- 推荐不是按时间排序，而是按**学生画像匹配度打分**
- 每一条都会说明「为什么推荐你参加」，而不是只给一个列表
- 报名倒计时是动态计算的（种子数据用了相对当前日期的表达式，任何时候演示都有倒计时）

---

## 第 5 步 · AI 助手与模拟面试（60 秒）

**操作**：
1. 进入「AI助手」
2. 先指向顶部的**AI 模式徽章**（在线 / 离线模板）
3. 在「通用问答」里发一条问题，让评审看到**逐字流式输出**效果
4. 切到「模拟面试」模式，输入「开始面试，我投递的是Java后端实习」

**讲解要点**：
- 流式输出用的是 NDJSON 而不是标准 SSE：模型回答里有大量换行，
  SSE 的单行 `data:` 格式会把换行后的内容丢掉，NDJSON 由前端按行解析，能完整保留 Markdown 结构
- 回答里的**表格、代码块、列表**都是真实渲染的，不是把换行替换成 `<br>`
- 「模拟面试」是独立模式，后端有专门的面试官提示词：先提问、再点评、再追问

---

## 第 6 步 · 成长档案与 AI 简历（45 秒）

**操作**：
1. 进入「成长档案」，展示项目 / 竞赛 / 证书 / 实习 / 荣誉的分类归档与统计
2. 进入「AI简历」，展示 A4 版式简历
3. 点「导出 / 打印」

**讲解要点**：
- 简历内容来自成长档案的真实数据，不是让 AI 凭空编造
- 可以直接浏览器打印导出 PDF，是真正能拿去投递的产物，而不是演示用的假页面

## 第 8 步 · 管理后台（如有时间，30 秒）

**准备**：用管理员账号登录 —— `13900000000` / `123456`，导航栏会出现「管理后台」图标。

**操作**：
1. 进入「管理后台」，展示顶部 8 个指标卡与两张图表
2. 在用户列表里搜索手机号或昵称
3. 在演示账号那一行点「设为管理员」

**讲解要点**：
- 这一页能讲的东西比想象中多：注册趋势、AI 使用分布（哪种对话模式学生用得最多）
- 权限是真的做了两层：前端路由守卫拦住普通学生，后端 `/api/admin/**` 校验 `ROLE_ADMIN`。
  可以现场用学生账号的 Token 调一次管理接口，会拿到 **403**
- 删用户会级联清理 9 张表的关联数据，并且拦住了「删除自己」和「删掉最后一名管理员」
- 角色改动要重新登录才生效——因为 JWT 是无状态的，Token 里带着角色快照。
  这个细节讲出来比单纯说「实现了权限管理」更有说服力

## 常见追问与回答

| 追问 | 回答要点 |
| --- | --- |
| AI 是真的在调用大模型吗？ | 是。`DeepSeekProvider` 调用 OpenAI 兼容协议；未配置 Key 或调用失败时降级为内置规则模板，并在界面明确标注「离线模板」，状态可通过 `/api/ai/status` 查询 |
| 用户自己的 Key 安全吗？ | Key 按用户隔离存在 `user_settings` 表，返回前端时做了脱敏（只显示前后 4 位），且不会出现在任何日志里 |
| 为什么不用 Spring Boot 3？ | 当前基于 Spring Boot 2.7 + JDK 8 编译，兼容性更好；升级到 3.x 需要 `javax` → `jakarta` 全量迁移，属于后续计划 |
| 密码怎么存的？ | BCrypt 加盐哈希，`/api/user/profile` 返回前显式置空密码字段 |
| 离线模式下画像会不会不准？ | 会，所以界面明确标注。离线模板只能覆盖常见情况，配置 Key 后才是完整的个性化分析 |
| 数据是随机生成的演示数据吗？ | 竞赛、课程、专业字典是真实调研整理的；演示账号的画像/规划/简历是为了让评审打开就有内容而预置的示例数据 |

---

## 演示时的注意事项

1. **提前登录**，不要在评审面前等待登录请求
2. **先看离线模式的效果**，再展示配置 Key 后的真实输出，对比更有说服力
3. 遇到 AI 响应慢时不要空等，先讲技术架构（流式输出、降级策略、可替换的 AIService）
4. 手机演示是加分项：项目已做移动端适配，可以直接用手机打开同一地址
