## 二、四档部署方式

### 档位 1：便携版（推荐评委复现）

```bash
# 完整解压作品包 -> 便携版-双击即用/
# Windows：双击 启动智途AI.bat（中文乱码时改双击 start-en.bat）
# macOS / Linux 或绕开 bat：
java -jar zhitu-ai.jar --spring.profiles.active=demo --server.port=8080
```

数据落在同目录 `./data/zhitu_ai_v3`，首次启动自动建库并导入 **175 个专业、101 场竞赛、262 门 B 站公开课**。8080 被占用时脚本自动切换 8090~8093。演示账号 `13800000000 / 123456`。

### 档位 2：源码开发（H2 或 MySQL）

```bash
bash scripts/init-db.sh          # Windows: scripts\init-db.bat（MySQL 档位才需要）
cd backend  && mvn spring-boot:run -Dspring-boot.run.profiles=demo
cd frontend && npm install && npm run dev
```

默认后端 8080、前端 3000（`/api` 已代理到 8080）。`demo` profile 使用 H2 相对路径 `./data/zhitu_ai_v3`；去掉 profile 即走 MySQL 连接。

### 档位 3：Docker Compose（MySQL + 后端 + 前端）

```bash
docker compose up -d --build
```

三容器：MySQL 8.0、Spring Boot 后端、Nginx 托管前端。端口与环境变量见 [docker-compose.yml](../docker-compose.yml)。

### 档位 4：分布式 / 生产数据库

`application-prod.yml`（不入库）中把 `spring.datasource` 指向 MySQL 主从、读写分离中间件或分布式数据库（如 TiDB / OceanBase 的 MySQL 协议端点）即可；业务层基于 MyBatis-Plus，SQL 全部使用标准 MySQL 方言，无 H2 专有语法。H2 与 MySQL 各有一份等价 DDL/种子脚本：

| 用途 | H2 | MySQL |
| --- | --- | --- |
| 建表 | `backend/src/main/resources/db/schema-h2.sql` | `database/schema.sql` |
| 竞赛/专业字典 | `backend/src/main/resources/db/data-h2.sql` | `database/data.sql` |
| B 站课程 262 门 | `backend/src/main/resources/db/bilibili-seed-h2.sql` | `database/bilibili-seed.sql` |

两份种子由 `scripts/gen-bilibili-seed.py` 统一生成，H2 用 `MERGE INTO ... KEY(title)`、MySQL 用 `ON DUPLICATE KEY UPDATE`，可重复执行、旧库幂等升级。

## 三、环境变量完整表

来源：`backend/src/main/resources/application.yml`、`application-demo.yml`；模板：[`.env.example`](../.env.example)。

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `SERVER_PORT` | `8080` | HTTP 端口 |
| `SPRING_PROFILES_ACTIVE` | `demo` | `demo`=H2；留空/`prod`=MySQL |
| `DB_HOST` / `DB_PORT` | `localhost` / `3306` | MySQL 地址 |
| `DB_NAME` | `zhitu_ai` | 库名 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / 占位 | MySQL 账号（仅本地默认值，生产必须改） |
| `AI_PROVIDER` | `deepseek` | 厂商标识（仅记录用） |
| `AI_API_KEY` | 空 | **留空也能完整演示**；用户亦可在「API 设置」页自带 Key，优先级高于系统 Key |
| `AI_API_URL` | `https://api.deepseek.com/v1` | 任意 OpenAI Chat Completions 兼容端点 |
| `AI_MODEL` | `deepseek-chat` | 文本模型 |
| `AI_VISION_MODEL` | 空 | 视觉模型，空则回退 `AI_MODEL` |
| `AI_TIMEOUT` | `60000` | 单次调用超时（ms） |
| `AI_MAX_RETRIES` | `2` | 失败重试次数，耗尽后诚实降级 |
| `AI_MAX_IMAGE_MB` | `5` | 证书图片大小上限 |
| `JWT_SECRET` | 占位串 | **生产必须替换为随机长串** |
| `JWT_EXPIRATION` | `86400000` | Token 有效期（ms） |
| `SQL_LOG_IMPL` | `StdOutImpl` | MyBatis 日志实现 |
| `ZHITU_BASE_URL` | `http://localhost:8080` | MCP Server 调用的后端地址 |
| `ZHITU_TOKEN` | 空 | MCP Server 使用的 JWT |

> 密钥处理：`application.yml` 只写 `${AI_API_KEY:}` 占位；`.env`、`application-prod.yml`、`application-local.yml`、`*.pem` 全部被 `.gitignore` 排除。前端「API 设置」页的 Key 以脱敏形式回显，出口由 `AiGuard.maskSecrets` 抹除 `sk-*`、Bearer 与手机号。**公开仓库中不存在任何真实 API Key。**

- `mcp-server/`：零第三方依赖的 Node 18+ 标准 MCP Server（stdio JSON-RPC）。

**锁定方式**：后端由 Maven parent 统一管理版本，前端使用 `package-lock.json`（如存在）或 `npm install` 解析 `^` 范围；无私有仓库、无付费依赖、无需要科学上网的源。

## 五、首次启动自检

1. `java -version` 有输出且 ≥ 1.8；
2. 启动后 `http://localhost:8080` 返回 200，静态资源 200；
3. 用 `13800000000 / 123456` 登录，首页、B站课堂、竞赛报名、简历编辑均可打开；
4. 新账号先引导完善档案，未完成档案时相关接口返回 409 + 通用文案，不出现 500 / NPE 堆栈；
5. `mvn test` 全绿（138 项），日志无 ERROR；
6. 仓库中无 `data/`、`*.mv.db`、`*.lock.db`、`.env` 或真实密钥。
